Live ArUco zone counter

Count how many people are in each zone of a camera view in real time, by detecting fiducial markers worn on heads. Self-hosted. Open source.

What it does

You're standing on the second floor of a hall. People downstairs walk into one of four zones marked on the floor — “Yes”, “No”, “Maybe”, “I don’t know”. Each person wears a small printed marker on their head. The system sees who’s in which zone, in real time, and lets you snapshot per-person answers across many questions.

It works because ArUco markers are fiducial markers designed for exactly this: small black-and-white squares detected reliably from far away with dozens in frame at once. Each marker carries a small integer ID linked to a person in the database.

Features

Real-time detection

Browser captures webcam, streams JPEG frames over WebSocket. OpenCV detects all visible markers per frame and assigns each to a zone polygon.

Admin panel

People, markers, zones, questions — full CRUD. Zones are drawn directly on the live camera feed by clicking polygon vertices.

Printable PDFs

3×3 markers per A4 page at 200 DPI. Each marker is captioned with its ID and the assigned person’s name. White quiet-zone padding for reliable detection.

Per-question snapshots

Mark a question active, hit “Record snapshot”, and the system saves where each detected marker was at that moment. Browse history, see per-zone counts.

Zero cloud dependencies

Everything runs in one Docker container. SQLite for storage. No accounts, no API keys.

Robust at distance

Default DICT_4X4_100 dictionary keeps the inner pattern simple, optimizing for detection from across a hall instead of marker count.

Architecture

┌──────────────┐ WebSocket (JPEG bytes) ┌──────────────────────┐ │ Browser │ ──────────────────────────────▶ │ FastAPI in Docker │ │ (webcam) │ ◀─── JSON: detections + zones ── │ OpenCV ArUco │ │ draws over- │ │ SQLite + PDF gen │ │ lay locally │ └──────────────────────┘ └──────────────┘

Docker on macOS can’t access the host webcam directly, so the browser captures the camera and ships compressed frames to the dockerized backend. Detection runs server-side for consistency; overlay drawing happens client-side. Bandwidth is ~300–500 KB/s at 10 fps, 1280×720.

Quick start

git clone https://github.com/baditaflorin/live_qr_code_counter_by_position.git
cd live_qr_code_counter_by_position
docker compose up --build

Open http://localhost:8000 for the live counter and http://localhost:8000/admin for the admin panel. Grant camera permission on the first Start click. Data persists in ./data/app.db.

Workflow

  1. Admin → People: add a person, choose how many markers to assign.
  2. Admin → Markers: download the printable PDF, print, cut, hand them out.
  3. Admin → Zones: start the camera, click polygon vertices on the video, name the zone (e.g. “Yes”), pick a color, save.
  4. Admin → Questions: create a question, mark it active.
  5. Live view: hit Start, watch live counts update per zone, hit Record snapshot to save the current per-person answer.
  6. Question results: review history, see per-zone breakdown, see which person was in which zone at each snapshot.

Why ArUco instead of QR codes

QR codes carry arbitrary text but are fragile at distance and angle, and standard detectors struggle with multiple QRs per frame. ArUco markers are designed exactly for fiducial detection at distance: faster, more robust, and handle dozens-per-frame trivially. Since each person only needs an integer ID (not arbitrary data), QR is overkill.

Tips for overhead cameras

  • Marker size: rule of thumb, the printed marker should be ≥1/40th of camera frame height. From a 2nd-floor hall view, that’s typically A5 (≈15×15 cm) for a 1080p camera.
  • Mount stiff: cardboard backing keeps the marker flat. Curling kills detection.
  • Lighting: diffuse light beats harsh single-point. Avoid shadows across the marker.
  • Resolution vs. FPS: 1280×720 @ 10 fps is the sweet spot for most rooms.
